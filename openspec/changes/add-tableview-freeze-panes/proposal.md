# Proposal

## Why

`CatTableView` 目前只能整体滚动：表头虽然在纵向固定，但左侧关键列和顶部关键行无法与主体同时保持可见。数据密集场景下对照、定位和编辑需要反复滚动，冻结窗格是这类表格的基础能力。

## What Changes

- 新增 `frozenColumnCount` 与 `frozenRowCount`，从起始侧连续冻结，RTL 自动镜像到右侧；表头不计入冻结行数。
- 冻结后形成四区布局：左上（冻结列 × 冻结行）、顶部（主体列 × 冻结行）、左侧（冻结列 × 主体行）、主体（主体列 × 主体行）。
- 右侧一条垂直滚动条跨四区统一；水平滚动条只覆盖主体区；表头分冻结段与主体段，冻结段固定、主体段随横向滚动。
- 冻结区与主体交互完全一致：可选中、可编辑、可调整列宽，键盘方向键可跨冻结边界导航。
- 冻结数量只由属性和方法修改；不提供表头拖拽抓手，应用可在自己的菜单或工具条中调用 API。
- 越界静默钳制到 `[0, 列数]` / `[0, 行数]`；冻结全部时隐藏对应滚动条；模型减少时自动收敛，不告警。
- 冻结区总宽/高超过视口时不做额外限制，主体可被压缩到 0，不引入冻结区内部滚动。
- 新增 `freezeTo(row, column)` 与 `clearFreeze()`；方法等价于写属性，不引入独立状态，后写覆盖先写。
- 运行时改变冻结数量只重排布局，保持滚动位置和选中项，按新的可滚范围钳制。
- 默认 `0/0` 时保持现有 `CatTableView` 行为不变。

## Impact

涉及 `src/uikit/qml/CatTableView.qml` 及新增的内部 QML 辅助组件、`src/uikit/CMakeLists.txt` 的 QML 模块登记、Gallery 数据页演示与中英文 TS、QML 行为测试，以及 `COMPONENTS.md`、`VALIDATION.md`。公开接口新增两个属性、两个方法；不改变 C++ 头、导出符号或 ABI。

非目标：非连续冻结、冻结区内部滚动、表头拖拽抓手、库内建右键菜单、多级表头、行号列、服务端分页。
